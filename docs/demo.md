# Demonstration plan (90 seconds)

This is a plan for demonstrating the real application, not a recorded video or static mockup.

Repository: https://github.com/Christiansada/weight-shift

Application: https://christiansada.github.io/weight-shift/

1. **0–15s / Problem:** Show the synthetic venue example. Explain that a weighted score can hide sensitivity to preferences. State that the numbers are illustrative, not venue observations.
2. **15–35s / Real interaction:** Point to the Library room / Community hall baseline tie at 80. Move Accessibility from 40% to 80%. Show Library room leading and the continuous score lines.
3. **35–50s / A different trade-off:** Select Facilities and move to 100%. Studio space leads. Return to baseline and inspect the interval/boundary disclosure. Explain that pairwise crossings are calculated, not sampled.
4. **50–65s / Inputs:** Edit a score; show immediate invalidation, apply it and inspect the new output. Reset. Import a two-option example from the editable JSON structure if time allows.
5. **65–80s / Audit:** Download the actual JSON and open it. Show scenario inputs, score lines, boundary ties and explored weights. Explain local computation, with no account or API.
6. **80–90s / Limits and invitation:** One varied weight, fixed subjective scores, compensatory preferences; no objective recommendation or uncertainty model. Show repository and app URLs. Invite numerical test cases, accessible interaction reviews and score-anchor improvements.

Capture the actual interface at desktop and mobile widths. Do not describe screenshots as an interactive demonstration. Verify the deployment before presenting these URLs as live. Social posts remain drafts until the owner chooses to publish them.
